[M2C1 / Autonomous Dev Framework discussion]

Phil: Can the coding agent work with Cortex?

James: So there's actually something built into Cortex called M2C1 Worker. M2C1 stands for Measure Twice, Cut Once. There's a worker agent template built into Cortex that you can tell your orchestrator to spin up - your orchestrator will basically go through the M2C1 process with another agent back and forth instead of you doing it with that agent.

Normally with this skill, the agent asks you a bunch of questions, you answer the questions, goes back and forth with you, and then it starts developing after that Q&A phase. Whereas with the M2C1 worker in Cortex, the orchestrator replaces you. So it answers all the worker's questions and they just go through the whole thing by themselves.

The core of this skill is these phases: brain dump creates a simple PRD, then a huge research wave with sub-agents, discovery questions, more research after discovery, it analyzes its own environment and suggests MCP servers, tool verification, creates custom skills for the project. It's a very involved process centered around one project.

Robert: How does that differ from Get Shit Done?

James: It's very similar - this is kind of based on Get Shit Done. The discovery questions between research waves was something I felt was missing from GSD. These three phases really shape each other - at the end you really have a well-researched plan that reflects your intentions. The tool evaluation step is super important - before you start, your agent evaluates its own tools to see if it could add MCP tools to help perform the execution more autonomously. Like if you're using Supabase, it will say "you should connect the Supabase MCP before we start." And then it creates custom skills for itself surrounding the research you've done about the project.
